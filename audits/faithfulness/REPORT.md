# OpenAI math (2026-10) Comparator の命題忠実性監査

- 監査日: 2026-10-29（監査役: Claude サブエージェント。報告書は主担当が代筆保存）
- 対象: 003, 005, 013, 084, 100, 134, 145, 161, 187, 189, 192, 245
- データ: `data/openai_math/lean/ComparatorChallenges/*.lean|json`、`lean/docs/NNN.md`、`preprints/*/paper.txt`（すべて読み取りのみ）
- 範囲: 「Lean の命題が論文の主張と同じことを言っているか」だけを判定した。証明本体（`lean/OAI`）はビルドも検証もしていない。

## 方法

1. Lean の主定理を、論文の主定理、および文献での標準的な定式化と比べた。
2. 主定理が依存する独自定義をすべて読み、標準からのずれや、自明に満たせる定義になっていないかを見た。
3. json の許可公理と宣言名を確認した。
4. 仮定が空にならないか、ジャンク値（s=1 の規約値、`tsum`、`sInf`）で主張が通ってしまわないかを見た。
5. 制限が doc の Scope 節で開示されているかを区別した。

**共通事項**:
- 20 本の json すべてで `permitted_axioms = [propext, Quot.sound, Classical.choice]`。
- challenge ファイルに `axiom` / `opaque` / `native_decide` / `implemented_by` / `unsafe` は無い。

## 個別の注記

- **003**
  - ζ と Dirichlet は Mathlib の標準定義を使っている。s=1 の規約値でも主張は弱まらない。
  - Hecke は独自定義。指数部分が exp(−πt·N(A+Bω)) になり、6 で割る正規化をすると標準の Hecke L 関数になること、非自明な指標では s=1 に極がないことを検算した。
  - Siegel 零点の主張は 7/8 の定理から c = 1/8 で自明に出るので、独立した内容はない。
- **084**
  - README の見出しは「すべての比率 q ∈ (0,1)」をうたって [Lean] にリンクしている。しかし Comparator が扱うのは q = 1/2 だけ。
  - 幾何数列の場合の論文（Oct 5）は doc にリンクされていない。
  - Scope に「dyadic case」と明記されているので未開示ではないが、見出しだけ読むと誤解を招く。
- **100**
  - K が辺長 2 の正四面体であること、A_min = √2 であることを検算した。A_min = H も主張に含まれているので、測度の正規化がずれていれば証明は通らない。
  - challenge ファイル内に `run_cmd Lean.modifyEnv … auxLemmasExt.setState env {}` が 10 か所ある。主張への影響はないとみられるが、異例なので注記する。
- **134**: doc の Scope は同じ段落を 3 回繰り返していて、編集が雑。
- **145**: Ω に標準空間を仮定していないので、文献より一般か同等。恒等写像は混合的でないので、仮定が空になることもない。
- **187**: Breaker の手は固定列だが、Maker の戦略が決定的なので、適応的な Breaker も含まれる。

## 今後

- 他の結果を監査するなら、「README の見出しと [Lean] リンク」を「Comparator の実際の範囲」と突き合わせるのが効率がよい（084 型の問題が見つかる）。
- challenge ファイル全体で `run_cmd Lean.modifyEnv` が 70 か所以上ある。`run_cmd do … elabCommand` 型（ThorpRouting など）は、Comparator がどこまでを信頼しているかという観点で別途確認する価値がある。
