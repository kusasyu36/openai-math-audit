## 0. 結論（先に）

2. その Lean の定理が正しく、命題が忠実なら、**029 の定理 1.2 はその特別な場合**（31/32 < 1 − 10⁻⁶）。したがって 142 の解析の入力（`10-analytic.tex:9`、`:39`）も、029 の証明ではなくこの Lean の定理から得られる。142 → 029 → 003 の鎖のうち「029 の定理 1.2 が誤っていれば両方崩れる」という危険は、**零点のない領域の入力に限っては**、Axiom の形式化が正しいかどうかに置き換わる。明示公式、一様な零点の数え上げ、判別式の評価、142 自身の帰着の正しさは別に必要（Codex w15）。
3. **Alpöge の Lean の定理（§1）は、029 の定理 1.2 も 142 の q ≥ 3 の入力も、その特別な場合としては含まない**。証明された 5 つの定理は、ζ のリーマン予想と、**ディリクレ L 関数**の一般化リーマン予想だけ（`sources/alpoge_Statements.lean`）。029 は円分体（それ自体は Q 上アーベル）上の一般の有限位数ヘッケ L 関数を扱う。対応する類体や、142 で必要となる Kummer 体 Q(μ₁₂q, p^{1/q})（q ≥ 3）は Q 上アーベルでなく、ディリクレ L 関数についての 5 命題の直接の対象ではない（Codex w15 の言い換え）。覚え書きは数体の場合（拡張リーマン予想）を「時間をかければ出ると期待している」と書くだけ（`sources/alpoge_remark.txt` 1 ページ目）。ここは「含まない」と言えるだけで、「導けない」とは言っていない。
4. QUESTIONS.md の 3 番（142 の命題 11.3 を q = 2 で使うと最小平方非剰余が (log p)^{20000000} 以下）は、**質問としては取り下げ、訂正の注記にする**。q = 2 の帰結に 003 を超える零点の定理は要らず、11-20 の公開時点で既にそうだった（下の「003 で既に」。Codex w15 が `data/openai_math/lean/ComparatorChallenges/DirichletSevenEighths.lean:8–11` で確認、主担当も確認）。ただし 003 の証明や、142 の明示公式から補助素数への議論の検証とは別。q = 2 の体 Q(μ₂₄, √p) は Q(μ₂₄ₚ) に含まれる（√p または √−p は Q(μₚ) に入り、i ∈ Q(μ₂₄)）ので、そのゼータ関数はディリクレ L 関数の積になり、Alpöge の定理（正しければ）か Axiom の 31/32（正しければ）からも同じ結論が出る（評価の良し悪しは計算していない）。**003 で既に**: q = 2 なら 142 の補題が要るのはディリクレ L 関数の一様な帯だけで、OpenAI 自身の 003（ディリクレ L 関数に 7/8、OpenAI が Lean 化、私たちの命題照合で「忠実」、`audits/faithfulness/REPORT.md:24`）で足りる。つまり 3 番は 11-20 に出した時点で、OpenAI 自身の形式化済みの結果から出ていた。私たちも Codex w14 も気づかなかった。GRH のもとでの最小平方非剰余の評価（Ankeny 1952、Bach 1990 の 2 log² p）の文献番号は、**本文に書く前に原典で確かめる**（未確認）。

## 1. Alpöge の発表（11-20）で確かめたこと

- 覚え書き（4 ページ）: https://alpo.ge/remark.pdf → `sources/alpoge_remark.txt`。主張は「RH の証明を Claude と見つけた。方法は GRH に及ぶ。ERH も時間をかければと期待」。人が読める証明は出していない（Lean だけを出すと明記）。2 ページ目で OpenAI の「Siegel の議論」（003 の一部と思われる。未照合）に触れている。

- Lean FRO と Mathlib Initiative の共同声明（11-21、`sources/lean_fro_joint_statement.txt`）: **RH の命題と証明だけ**を認定。ディリクレ版には触れていない。

## 2. Axiom Math の形式化（10-12〜13、見落としていたもの）

- リポジトリ: https://github.com/AxiomMath/DedekindZetaZeroFree （作成 10-12、最終コミット 09afbb4 が 10-13、CI「Lean verification」は成功）。CI の成功はビルドが通ったという意味で、Lean は `sorry` を警告だけでビルドする。標準の 3 公理だけという点は Axiom の README の記述で、私たちは確かめていない。README → `sources/axiom_README.md`。論文は Hexagon の 2610.00200（v1 は別の主張だったと二次資料にある。未確認）。
- 主張（README による）: すべての数体 K で ζ_K は Re s > 31/32 に零点を持たない（定理 1.1）。有限位数のヘッケ L 関数も同じ（系 1.2）。標準の 3 公理だけ。README は「Cureton と Thorner が研究を指揮し、AxiomProver が証明と Lean を生成した」と書く。openai/math の解析数論のコードを一部流用している。
- 命題（`sources/axiom_DedekindZetaChallenge.lean`、45 行）の私の読み:
  - `main`: ℂ∖{1} で正則な f が存在し、Re s > 1 で `NumberField.dedekindZeta K s`（Mathlib）に一致し、Re s > 31/32、s ≠ 1 で f s ≠ 0。ℂ∖{1} は連結なので f は解析接続そのもの。
  - `heckeCorollary`: `RayClassCharacter K m` は、イデアル上の乗法的関数で、m と素でないイデアルで 0、α ≡ 1 (mod m) かつ総正の α の単項イデアルで 1。つまり狭義射類群の指標で、有限位数のヘッケ指標はすべてこの形で表せる（と私は理解している）。L 関数は Re s > 1 の級数で特徴づけ、Re s > 31/32 で（主指標なら s ≠ 1 で）0 にならない。
  - 029 の定理 1.2（`Primitive-roots-…/sections/01-introduction.tex:38–45`）の「cyclotomic F ⊃ μ₁₂、有限位数ヘッケ指標 η、L_F(s,η) の有理型接続は Re s > 1 − 10⁻⁶ に零点を持たない」は、K = F、適当な m でこの系の特別な場合に見える。原始指標と非原始指標の違いは有限個の Euler 因子で、Re s > 0 では零点を生まない。
  - 142 が実際に使うのは補題 `analytic:explicit`（`10-analytic.tex:39–50`）の仮定「ζ_M が Re s > 1 − δ に零点を持たない」で、M = Q(μ₁₂q, p^{1/q}) と K = Q(μ₁₂q)（`:101–103`）。これは `main` の特別な場合。
- しなかったこと: ビルド、公理の確認、comparator の実行（5,544 ファイル。手元の容量と規則の両方から、今は行わない）。
- 第三者の確認: QuasiRiemannTracker（ディリクレ L 関数の零点の境界を CI で検証して載せる追跡サイト）に Axiom の結果を載せる PR #114（11-03、未マージ）がある。本文に「No adapted-source Lean build, Comparator or independent kernel replay has been run」「Admission remains pending」とある。Dean Cureton が掲載を了承するコメントを付けている。同じ PR のコメントは、Liu の Hexagon 2610.00655v2 が全数体で 0.8740… を主張していると紹介している（未読）。**独立の検証の公表は、読んだ範囲では見つからなかった**。n-Category Café の記事はサイトに接続できず未読。
